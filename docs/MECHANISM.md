# 技术说明：1360ms 整池复用

基于 South-Bridge 的 C3.11 机制分析。以下只是固定版本的地址与资源布局知识；不分发原厂机器码或 PCM。

## 布局

| 音色资源组 | ROM 起点 | RAM 起点 | 资源总量 |
|---|---|---|---|
| B | 0x43FBB850 | 0xA15C1B200 | 65280 B |
| C | 0x43FCB750 | 0xA15C2B100 | 65280 B |
| D | 0x43FDB650 | 0xA15C3B000 | 65280 B |
| E | 0x43FEB550 | 0xA15C4AF00 | 65280 B |

原始初始化中 B/C/D/E 各有 28800 / 9600 / 19200 / 7680 字节的四次复制。
16 次复制在 ROM 与 RAM 都连续。合计 261120 字节，池尾分别为 0x43FFB450 和 0xA15C5AE00（不包含尾地址）。
容量来自实际初始化映射，不依赖原脚本 TYPE_RES 中单个音色的拼接长度。

48kHz × 2 声道 × 2 字节 = 每秒 192000 字节，所以整池等于 1360ms。

## 五个修改窗口

| 地址 | 大小 | 改动 |
|---|---|---|
| 0x40E347B4 | 20 B | 原 B 前段地址 getter 退役，改成私有 32 位长度 getter |
| 0x43FB7DF0 | 8 B | B 前段地址入口指向 B 块首 getter 0x40E347A0 |
| 0x43FB7EB8 | 8 B | B 主段长度入口指向新 getter |
| 0x43FB7EC0 | 8 B | B 前段长度入口指向新 getter |
| 0x43FBB850 | 261120 B | 使用转换后的整池 PCM |

此外重新计算 EG 最后两个 CRC 字节。其他字节必须与基底完全一致。

新的 getter 用本项目自行编码的 MOVZ W0 / MOVK W0 / RET 返回 261120，避免将大于 65535 的字节数仅编码在一个 16 位立即数字段里。
它复用已有可执行函数空间，不申请新 RAM，也不寻找未知代码洞。

B 前段的地址引用先被重定向，原函数空间才用于长度；仅对已知直接跳转和 64 位指针字面量检查其旧引用。
这不是任意间接/计算调用不存在的形式证明。完整启动和实机行为仍需独立验证。

共享长度 getter 保持原厂值。C/D/E 地址与长度入口不改，因此选择它们会读取被覆盖后的短片段或静音。
B 的中段/终段入口也不延长，慢门仍可能在前段之外播放这些片段。

## 音频处理

输入只接受 PCM16、48kHz、立体声 WAV。严格检查实际帧数与数据完整性，超过 65280 帧就报错。
调用固定哈希的原始 load_wav(path,65280)，由原转换器补静音、对最终 20ms 做渐隐、按 84% 峰值归一化。

短音频的补静音位于素材之后；若最终 20ms 落在补静音区，就不会另在素材末尾新增渐隐。
没有重采样、裁剪或变速。preview.wav 是转换结果，不能当作实机输出证据。

## 哪些没有改

- 原有的资源初始化复制指令；
- cap 裁切机制、消息队列、快门事件时序和完成回调；
- 高速连拍独立路径与 A 资源；
- 版本身份与完整更新包的封装流程。

长声音仍可能被打断、截短、重复或附带尾音。1360ms 的请求不等于真实模式下必然提交/播出 1360ms。

## EG 基底兼容性

必须另行提供固定哈希的原始 C3.11 EG。可选择干净的功能补丁 EG 作为基底，但声音初始化、分发表、相关 getter 和整个 B/C/D/E PCM 池必须仍与原始 EG 相同。

这种检查能检测已有声音补丁或窗口冲突，不构成对任意第三方补丁的兼容保证。
工具只验证相对基底的修改范围，不重新证明基底本身的拍摄功能、安全性或其上游配方。
外层更新包和版本号由用户自己的整合工具处理。不要反复将已修改的声音模块当输入。
